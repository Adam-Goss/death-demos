# Domain docs

This is a single-context repo. Its glossary belongs at the root as `GLOSSARY.md`; architecture decisions belong in `docs/adr/`.

Before exploring an area, read the glossary and relevant ADRs if they exist. Their absence does not require setup work; domain-modeling creates them when useful.

Use glossary terms in issues, proposals, tests, and code discussions. If a needed term is missing, reconsider it or record the gap for domain-modeling. Flag any conflict with an ADR explicitly.
