# Guacamole gateway for browser access to the attacker and targets

All lab access was SSH or CLI over the VPN. We add a dedicated **Gateway VM** running Apache Guacamole so the operator gets a browser GUI to the attacker and a terminal to each target, as the foundation for a later malware-analysis zone.

The gateway is its own guest in its own zone (`10.77.2.10`, `10.77.2.0/24`, its own Tofu stack, pool and token), on the admin path behind the firewall VM's VPN. It does not run on the Proxmox host, the firewall VM or Elastic, and it has no route from the home LAN. The firewall allows the operator in over the VPN (HTTPS `443`, SSH `22` for provisioning) and the gateway out only to the attacker (RDP `3389`) and targets (SSH `22`). It reaches package sources only in maintenance mode, like every other guest that updates. This keeps ADR 0001's single enforcement point and adds one zone and one NIC to the firewall, not a bypass.

Only the attacker gets a desktop (XFCE and xrdp). Targets are deliberately vulnerable, so they get an SSH terminal only: no desktop, no extra attack surface, no extra telemetry. The firewall VM and Elastic are not brokered and keep their direct VPN routes. Direct operator RDP to the attacker stays denied, so the desktop is reachable only through the gateway. The attacker is the adversary and is not enrolled in Fleet, so the desktop adds no telemetry to the evidence store.

Authentication is Guacamole's local database with TOTP, for a single operator account, with no external identity provider. The default `guacadmin` password is replaced at provisioning and TOTP is checked by `scripts/guacctl.py check`. Secrets (the admin password, the attacker's RDP login) come from the operator environment and never the repo; the database password, TLS key and the gateway's SSH key to the targets are generated on the VM. The SSH key is authorised on targets for the gateway's address only. Guacamole stores connection credentials in its database, so a compromised gateway exposes them; rebuild it to rotate.

Consequences: the gateway joins the shutdown and startup order (shut down first, start last), the A2 probe matrix gains the gateway flows in both modes, and a new zone needs a sixth firewall NIC, so adding it rebuilds the firewall from a regenerated seed.
