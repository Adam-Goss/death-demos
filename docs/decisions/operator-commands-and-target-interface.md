# Operator commands and the target interface (M5)

Supports issue #24. Builds on `deployment-and-reset-lifecycle.md` (#8), `telemetry-contracts-and-budgets.md` (#9), `first-targets-and-hunt-outcomes.md` (#7). Written while M4 (#23) was unmerged: this file is the **contract M5 assumes from M4**; reconcile when M4 merges (list in [the runbook](../runbooks/m5-attacker-operator.md#reconcile-when-m4-merges)).

## Decisions

| Question | Decision |
| --- | --- |
| Attacker stack | **Own Tofu stack, pool `lab-attacker`, token and state** (`tofu/stacks/attacker`). A target reset (targets stack) cannot rebuild it; "attacker-side state is cleared separately" (#8) is `labops.py attacker-clean`. |
| Exercise ID | `labops.py exercise start ID --target T` writes an `exercise-start` marker to data stream `logs-lab_marker.events-default` with `lab.exercise_id`, `lab.target_id`, `lab.rebuild_generation`; `exercise end` writes `exercise-end`. One active exercise (#9). Refuses unless the firewall is in exercise mode with T selected, Elastic answers, and disk is below the high watermark (90%, #9: "stop new exercises"). |
| Finding an exercise's events | `exercise end` stamps `lab.exercise_id` on the target's events (same generation) between the start and end markers, widened by `ops.tag_slack_s`; `exercise tag ID` repeats it for events still in transit. The marker window (`exercise show ID`) and the Apache User-Agent (`opaleye-exercise1/<id>`) remain as cross-checks. Changed from "not stamped" at A6 (Adam, 2026-10-30). |
| Generation | Owned by M4's `scripts/target.sh` (`.state/targets/<t>.generation`, starts at 1, feeds Tofu `rebuild_generation` and Ansible). `labops.py` only reads it (`generation T`) to stamp markers and drain lines. |
| Drain marker | `labops.py drain T` SSHes to the target and appends `OPALEYE_DRAIN_MARKER token=<hex> target_id=T rebuild_generation=N` to `/var/log/dvwa/apache2/drain.log` (created by the target role; added to the Apache access stream's path list in `fleetctl.py`, so it uses the same agent, fingerprint setting and `lab-stamp` pipeline). so arrival proves the same pipeline drained. Confirmed by searching `logs-*` for the token with matching `lab.rebuild_generation`. Mechanism-agnostic about the data stream. |
| Reset | `labops.py reset T [--acknowledge-loss REASON]`: T must be a target with a VM in `plan.targets` (`t1`; `t2` has none); firewall in **maintenance mode** (provisioning pulls images/packages); no active exercise on T; **Elastic must answer (no override)**; drain must pass unless loss is acknowledged with a reason of 5+ characters (audited). Then `target.sh bump T --acknowledge-no-drain-check` (the drain check is this command's) and `target.sh provision T` (Tofu replaces the VM via the generation trigger, Ansible re-provisions; `fleetctl issue-token` retires the old agent and tokens). No other stack is addressed. |
| Shutdown | `labops.py shutdown`: graceful ACPI shutdown through the Proxmox API (no stop/delete/config call exists in the client), order gateway (when deployed), attacker, targets, firewall; startup is the reverse. The Guacamole gateway (#51) joined the order after M6. **Elastic is left running unless `--include-elastic`**, which only adds a graceful shutdown with Elastic's own token. Refused during an active exercise. Running targets are drained first (same check and override as reset: `--acknowledge-loss REASON`; Elastic must answer or loss be acknowledged). `startup` is the reverse (firewall first). |
| Evidence deletion | `scripts/evidence_delete.py`: separate file, not imported by or referenced from reset, shutdown, `lab.sh` or `pve.py` (tests assert it). `all` or `exercise:ID`; dry run by default; needs `--confirm` with the phrase the dry run prints (`DELETE EVIDENCE <scope> (<N> documents)`, so it matches what was previewed); refused during an active exercise, judged from local state **and** Elastic's own markers (unmatched start); exercise scope also removes firewall flow rows in the window; metrics never touched; audited. |

Elastic's 9200 is reached over an SSH tunnel (`scripts/elastic-tunnel.sh`), not directly over the VPN: the firewall allows the operator only Kibana and SSH (probes p32, p45, p48, p49), so the management-interface wording in ADR 0001 is met by Kibana on 5601 and the tunnel originates on the VM.
